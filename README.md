# Java Movies Hub — REST API для коллекции фильмов

**Java Movies Hub** — учебное backend-приложение на Java для управления коллекцией фильмов через HTTP API. Сервис позволяет добавлять фильмы, получать список и отдельные записи, фильтровать коллекцию по году выпуска и удалять фильмы.

Проект реализован **без Spring**: используется встроенный HTTP-сервер JDK, библиотека Gson для JSON и потокобезопасное хранилище в памяти. Это практика разработки HTTP API, валидации данных, обработки ошибок и интеграционного тестирования.

## Возможности

- Добавление фильма с автоматическим присвоением ID.
- Получение всех фильмов или фильма по ID.
- Фильтрация списка по году выпуска.
- Удаление фильма по ID.
- Проверка названия и года выпуска.
- JSON-ответы и HTTP-коды для успешных и ошибочных запросов.
- Интеграционные тесты с настоящими HTTP-запросами.

## Технологии

- **Java 11+** — HTTP-сервер (`com.sun.net.httpserver.HttpServer`) и HTTP-клиент для тестов (`java.net.http.HttpClient`).
- **Gson 2.10.1** — сериализация и разбор JSON.
- **Java Collections / ConcurrentHashMap** — хранение фильмов в памяти.
- **AtomicLong** — генерация идентификаторов.
- **Stream API** — фильтрация фильмов по году.
- **JUnit 5** — интеграционное тестирование API.

В проекте нет Spring Boot, базы данных, Maven или Gradle. Необходимые JAR-библиотеки находятся в `lib/`.

## HTTP API

Базовый адрес после запуска: `http://localhost:8080`.

| Метод | Адрес | Назначение | Успешный код |
|---|---|---|---|
| `GET` | `/movies` | Получить все фильмы | `200 OK` |
| `GET` | `/movies?year=2020` | Найти фильмы по году выпуска | `200 OK` |
| `GET` | `/movies/{id}` | Получить фильм по ID | `200 OK` |
| `POST` | `/movies` | Добавить фильм | `201 Created` |
| `DELETE` | `/movies/{id}` | Удалить фильм | `204 No Content` |

### Примеры запросов

**Добавить фильм:**

```bash
curl -X POST http://localhost:8080/movies \
  -H "Content-Type: application/json" \
  -d '{"title":"Inception","year":2010}'
```

Пример ответа (`201 Created`):

```json
{"id":1,"title":"Inception","year":2010}
```

**Получить список фильмов:**

```bash
curl http://localhost:8080/movies
```

**Найти фильмы за определённый год:**

```bash
curl "http://localhost:8080/movies?year=2010"
```

**Получить фильм по ID:**

```bash
curl http://localhost:8080/movies/1
```

**Удалить фильм:**

```bash
curl -X DELETE -i http://localhost:8080/movies/1
```

При успешном удалении сервер возвращает `204 No Content` без тела ответа.

## Валидация и обработка ошибок

При создании фильма проверяются:

- `title` — обязательное непустое название длиной до 100 символов;
- `year` — обязательное целое число от **1888** до **следующего календарного года** включительно;
- `Content-Type` — запрос должен содержать `application/json`;
- тело запроса — должно содержать корректный JSON.

Примеры кодов ошибок:

| Код | Причина |
|---|---|
| `400 Bad Request` | Некорректный JSON, ID или параметр года |
| `404 Not Found` | Фильм с указанным ID не найден |
| `405 Method Not Allowed` | Неподдерживаемый HTTP-метод |
| `415 Unsupported Media Type` | Неподходящий `Content-Type` при добавлении |
| `422 Unprocessable Entity` | Ошибка валидации названия или года |
| `500 Internal Server Error` | Необработанная ошибка на стороне сервера |

Пример ответа при пустом названии (`422`):

```json
{
  "error": "Ошибка валидации",
  "details": ["название не должно быть пустым"]
}
```

## Архитектура

```text
src/main/ru/practicum/moviehub/
├── MovieHubApp.java         # Запуск приложения
├── api/
│   └── ErrorResponse.java   # Модель ответа об ошибке
├── http/
│   ├── MoviesServer.java    # Конфигурация HTTP-сервера
│   ├── MoviesHandler.java   # Маршрутизация и обработка запросов
│   └── BaseHttpHandler.java # JSON, валидация и ответы
├── model/
│   └── Movie.java           # Модель фильма
└── store/
    └── MoviesStore.java     # Хранилище в памяти

src/test/ru/practicum/moviehub/http/
├── MoviesApiTest.java       # Интеграционные HTTP-тесты
└── ListOfMoviesTypeToken.java

lib/                         # Gson и JUnit
.github/workflows/           # Workflow из учебного репозитория
```

Разделение ответственности:

1. **HTTP-слой** принимает запросы, проверяет данные и формирует ответы.
2. **Модель** описывает фильм: `id`, `title`, `year`.
3. **Хранилище** управляет коллекцией фильмов с помощью `ConcurrentHashMap` и `AtomicLong`.

Данные хранятся **только в памяти**: после перезапуска сервера коллекция очищается.

## Запуск

**Требования:** JDK 11 или новее. Сборка исходников и тестов проверена с `--release 11` на JDK 21. Сам HTTP API проверен на Java 21.

### Через терминал (Linux/macOS)

Из корня репозитория:

```bash
mkdir -p out/classes
javac -encoding UTF-8 -cp "lib/*" -d out/classes $(find src/main -name '*.java')
java -cp "out/classes:lib/*" ru.practicum.moviehub.MovieHubApp
```

Сервер слушает порт **8080**. Для проверки откройте другой терминал:

```bash
curl http://localhost:8080/movies
```

Для пустой коллекции ответ будет `[]`.

### Через IntelliJ IDEA

1. Откройте репозиторий в IntelliJ IDEA и укажите JDK 11+.
2. Пометьте `src/main` как **Sources Root**, а `src/test` — как **Test Sources Root**, если это не сделано автоматически.
3. Добавьте JAR-файлы из каталога `lib/` в зависимости модуля.
4. Запустите `main()` класса `ru.practicum.moviehub.MovieHubApp`.

Если порт 8080 занят, приложение не запустится до освобождения порта или изменения порта в `MovieHubApp`.

## Тестирование

В классе `MoviesApiTest` находятся **23 метода `@Test` на JUnit 5**. Они выполняют HTTP-запросы к тестовому серверу и проверяют:

- получение пустой и заполненной коллекции;
- создание фильма и получение по ID;
- фильтрацию по году выпуска;
- удаление фильма;
- обязательные поля, предельную длину названия и диапазон года;
- некорректный JSON и `Content-Type`;
- коды ошибок для несуществующих фильмов и неправильных запросов.

Перед каждым тестом хранилище очищается. Тестовый сервер использует **порт 8080**, поэтому перед запуском тестов убедитесь, что другое приложение его не занимает.

**Запуск в IntelliJ IDEA:** откройте `MoviesApiTest` и выберите **Run**. JUnit 5 доступен в `lib/`.

Исходники тестов успешно компилируются на Java 21, в том числе в режиме совместимости с Java 11. Полный прогон через стандартный JUnit Runner при подготовке этого README не выполнялся.

## Ограничения и дальнейшие улучшения

- **Нет постоянного хранения:** все данные теряются при остановке сервера.
- **Нет авторизации, пагинации и изменения фильма** (`PUT`/`PATCH`).
- **Нет Maven/Gradle:** зависимости подключаются вручную.
- **Не все граничные случаи HTTP/JSON обработаны:** например, `POST` на вложенный путь `/movies/anything` сейчас тоже может добавить фильм, а некоторые некорректные JSON-значения приводят к ошибке `500`.
- **Порядок выдачи фильмов не гарантирован**, так как используется `ConcurrentHashMap`.
- **CI-workflow** вызывает готовую проверку из учебного репозитория Яндекс Практикума; это не самостоятельно написанный pipeline.

Возможные улучшения: подключить Maven/Gradle, дополнить проверки входящих запросов, добавить устойчивое хранение в базе данных, покрыть новые граничные случаи тестами и реализовать обновление фильмов.
